### 1.5 Q1 ANSWERED: what precedes a "1 parts" row with no refusal before it

It is a GATE FAILURE, not a mesh refusal - the mesh is never called. ground-vehicle-move-to.lua
:1570-1581 makes `Select off-road nav planning or feature planning` a **fallback selector** over two
children: the sequence `Maybe plan off-road nav path` (:1461-1470 = isRoadFollowingDisabled ->
**isCurrentPointInNavArea** -> isDestInNavArea -> createOffroadSegment -> calcOffroadNavPath) and
then `planOffroadFeatPath`. Any failure in that sequence - including the second node - drops
straight to the feature planner, whose job node is `Plan path` (:1371-1407, `computePathThroughFeatures`)
and whose print is `Planned path has N parts.` (:1398). `isCurrentPointInNavArea` is
`isPointInNavArea(this:getLocation3D())` (:1416-1420). Verbatim from run A, M1A2 1, subtask 1:

    w=29.20 16:51:37.644Z L3  ...Subtask 1 name and parameters: ground-vehicle-move-to: destination={...}
    w=29.20 16:51:37.644Z L4  .   Creating selector, "Primitive or Planned Move"
    w=29.30 16:51:37.744Z L4  .            fail in action Is current point in nav area?
    w=29.30 16:51:37.744Z L3  Not using roads for move planning.

    w=29.40 16:51:37.844Z L3  Planned path has 1 parts.

There is no destination-gate row and no `Calc off road nav path part` row: the mesh query was never
issued. Contrast the same member 10.7 s later (subtask 8): `Node Is current point in nav area?:

### 2.4 THE CAUSE OF THE G6 REFUSALS, AS THE EVIDENCE SUPPORTS IT

**Claim: the cause is the FLAT query itself - `useAbstractGraphs = false` in the shipped
ground-vehicle-move-to.lua - not seam connectivity, not the working-memory limit, not the per-frame
time budget, and not a length or sector-count ceiling.** Supporting facts, each from a row in these
runs: (a) the same area, legs, performer and build plan 8 of 8 long queries with the flag flipped and
2 of 24 without it, p = 4.3e-6; (b) the flag is the only functional line that differs between the two
scenarios (verified at byte level in the .scn and the .lua); (c) the two appData knobs the
documentation offers - the only ones tied to path planning - moved nothing; (d) a pure ceiling is
falsified inside one run by D's M1A2 1 planning 5,013.7 m / 10 seams and refusing 4,550.2 m / 9 seams

**CR4 - "the relocated appData was never read by the sim, so runs A, B and D measure nothing about
