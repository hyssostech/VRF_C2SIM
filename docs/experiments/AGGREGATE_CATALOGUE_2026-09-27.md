## 1. What a .magx is, and why the object types are RESOLVED here

- A `.magx` is a boost-serialised `UnitTypeMap`: `<first>` object type -> `<second>` unit ELEMENT
  definition. It sits beside the `.leaf` element definitions (MIL-STD icon visualizers) under
  `gui\visuals\Unit` and is merged by the vrfGui option `--mergeUnitTypeMap` (UG52 Table 10 p172).
- The SIMULATOR picks the template for a requested type by the best-match rule over the `.entity`
  matchType fields (ported from `src/VrfC2SimApp/ObjectTypeResolver.cs`). Every row's `selfResolves`
  column is that rule applied to the row's own type; the map validator applies it to every map row.
- ROLE comes from the platform file. UNIT = `AggregateLevelAggregate.ope`, one simulated object with
  combat power, health and a footprint (UG52 27.1 p528). CONTAINER = `PseudoAggregate.ope`, the
  "Aggregate Container" (UG52 72.2.1 p1419; Table 80 p1688 "Unit Container"): no warfare model
  and no movement system of its own; its Move Along Route is `PA_Move_Along_Route.lua`, which tasks
  each subordinate and ends when all have finished (`tick()`: `allSubordinatesComplete()` ->
  `endTask(true)`) - so an EMPTY container's move completes at once and nothing moves.
